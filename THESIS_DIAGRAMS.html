Diagram 1

System Architecture Diagram

EduGrant follows a three-tier web architecture deployed on cloud infrastructure. The client tier is any modern web browser. The application tier is a Django (Python) application hosted on Vercel as a serverless deployment. The data tier consists of a Neon PostgreSQL database for structured records and Cloudinary for document file storage. An external SMTP service handles automated email notifications.

Figure 1 · EduGrant System Architecture — Three-tier architecture: Client (Browser), Application (Django on Vercel with Rule Engine and Reports modules), and Data (Neon PostgreSQL, Cloudinary, WhiteNoise), with external Email Service.
Diagram 2

Rule-Based Analytics Flowchart

When an applicant submits an application, the rule evaluation engine retrieves the eligibility rules configured for that scholarship program and evaluates each condition using IF-THEN logic. If all conditions are met, a PASS result is stored; otherwise, a FLAG is generated with the specific violated conditions recorded. The result is displayed to administrators for final review and decision-making.

Figure 2 · Rule-Based Analytics Flowchart — IF-THEN screening engine flow from application submission through rule evaluation to PASS/FLAG result generation and administrator display.
Diagram 3

Descriptive Analytics Flowchart

When an administrator accesses the Reports page, the system retrieves records from the database and applies any active date filter. An aggregation engine groups, counts, and summarizes data by application status, program type, barangay, and submission period. The results are rendered as dashboard statistics and charts. The administrator may then export the data as a CSV file or print a formatted PDF report.

Figure 3 · Descriptive Analytics Flowchart — Process from administrator access through optional date filtering, database retrieval, aggregation, dashboard display, and optional CSV/PDF export.

Diagram 5

Data Flow Diagram — Level 0 (Context Diagram)

The Level 0 DFD presents EduGrant as a single system process and identifies all external entities. The Applicant submits registration information, application data, and documents, and receives status notifications in return. CAYDO Staff submits review decisions and receives application data, screening results, and reports. An external Email Service delivers automated notifications to applicants.

Figure 4 · DFD Level 0 — Context Diagram showing EduGrant as a single process with three external entities: Applicant, CAYDO Staff, and Email Service.

Evaluation Results — ISO/IEC 25010 Criterion Overview

EduGrant was evaluated by 80 respondents using the ISO/IEC 25010 Software Quality Model. Weighted mean scores were computed across eight quality characteristics using a five-point Likert scale. All eight criteria received scores in the Very Satisfactory range, with an overall weighted mean of 4.25.
